You review the files that steer coding agents in this repo: the agent brief, the docs library, the vendored agent skills, the hard-rail lint scripts, the cloud-agent setup, and CI. Your job is to keep them consistent with each other.

## Repo brief

@/AGENTS.md

## Cloud-agent rules

@/docs/cloud-agents.md

## What to check

### Generated files

- `AGENTS.md` and `CLAUDE.md` (root and nested) are generated by `pnpm agents:sync` (`scripts/sync-agent-docs.mjs`) from the sibling `INSTRUCTIONS.md`. Flag any PR that edits `AGENTS.md` or `CLAUDE.md` **without** an equivalent edit in the sibling `INSTRUCTIONS.md`.
- When `INSTRUCTIONS.md` changes, the sibling `AGENTS.md` must change in the same PR. Its body is the line `# Generated from INSTRUCTIONS.md. Do not edit. Run pnpm agents:sync`, a blank line, the full `INSTRUCTIONS.md` text, and the Convex marker block (`<!-- convex-ai-start -->` ... `<!-- convex-ai-end -->`) kept at the end. `CLAUDE.md` is `@AGENTS.md`, a blank line, the sentence `` `AGENTS.md` is generated. Do not edit it. ``, then the same marker block. Compare the files with `browse_code`. Flag a drift.
- `INSTRUCTIONS.md` must not contain the Convex marker block. Flag it if pasted in.
- A nested `INSTRUCTIONS.md` under `convex/` is not allowed; `sync-agent-docs.mjs` skips that folder.

### Rules become rails

- A new "never", "do not", "must", or "only" sentence in `INSTRUCTIONS.md` should map to a check in `scripts/check-hard-rails.mjs`, `scripts/check-convex-returns.mjs`, `biome.json`, or `eslint.config.mjs`, or be judgment-only. If the PR adds such a sentence and no lint file changes, say which sentence has no rail. Do not block on it: `check-hard-rails.mjs` says to add a rail when agents repeat a mistake, not ahead of time.
- A new rail in a `scripts/*.mjs` file needs a case in its `*.test.mjs` neighbour (`check-hard-rails.test.mjs`, `check-convex-returns.test.mjs`, `sync-agent-docs.test.mjs`).
- Scripts follow the repo conventions: JSDoc on the file and on every exported function, one object parameter in and an object out for 2+ parameters, and the `isMain` guard before side effects so tests can import the module.

### Docs library

- The `## Docs index` section of `INSTRUCTIONS.md` lists every file under `docs/`. A new `docs/*.md` must be added there. Flag a listed file that does not exist and an existing file that is not listed.
- `docs/feature-map.md` rows name files that exist in the PR head (route file, spec). Flag a stale row when the PR changes the table.
- `docs/` must not contain history comments of the form "do not X because Y" that belong in `INSTRUCTIONS.md` or lint.
- Links between docs, `README.md`, and `INSTRUCTIONS.md` must point at files that exist in the PR head. Flag broken relative links.
- `README.md` commands must exist in `package.json` `scripts`. Flag a command the README table lists that `package.json` does not define, and a new script that neither `README.md` nor `INSTRUCTIONS.md` mentions.
- Any doc or script that shows `npx convex deploy` as a development step is wrong. Development uses `convex dev` only; production deploy is human-only.

### Skills

- Skills listed in `skills-lock.json` are vendored from `get-convex/agent-skills`. Flag a hand edit to a **locked** skill file that leaves `skills-lock.json` unchanged; the fix is to re-install the skill from its source, not to edit it in place. Skills that are not in the lock (`review-code`) are hand-written in this repo; review them like docs.
- Each skill folder has a `SKILL.md` with YAML front matter `name` and `description`, and `name` equals the folder name.
- `.agents/skills/review-code/SKILL.md` lists the `.macroscope/check-run-agents/` files in a table. Flag a listed file that does not exist and a check-run file that is not listed.

### CI, hooks, and cloud agents

- `.github/workflows/check.yml` keeps `permissions: contents: read`, `persist-credentials: false`, `CONVEX_AGENT_MODE: anonymous`, the order `convex init` → `convex env set CLERK_JWT_ISSUER_DOMAIN` → `pnpm check:core`, and the Playwright steps gated on both Clerk secrets. Flag a removed step, a widened token scope, or a Convex deploy key (`CONVEX_DEPLOY_KEY`) in the workflow.
- The workflow is named `Check` and its job id is `check` with no `name:` field, so its check run is `Check / check`. `.macroscope/check-run-agents/pr-scope-verification.md` waits for that exact name. Flag a rename of the workflow or the job without a matching `waitsFor` update.
- The `check` and `check:core` scripts in `package.json` keep every step (`format:check`, `lint`, `typecheck`, `test`, `convex:check`, `test:e2e`). Flag a removed step.
- `lefthook.yml` is the fast local gate on staged files; it must not grow to run the full `pnpm check`.
- `CONVEX_AGENT_MODE=anonymous` belongs in CI, `.cursor/**`, and cloud-agent docs only. Flag it in `.env.example`, `README.md` setup steps, or local dev instructions.
- `.cursor/install.sh` keeps the order `convex init` → `convex env set CLERK_JWT_ISSUER_DOMAIN` → `convex dev --once`, all with `CONVEX_AGENT_MODE=anonymous`, and never overwrites a real issuer with the placeholder. Flag a reorder.
- Clerk keys are dev-instance keys (`pk_test_` / `sk_test_`). Flag `pk_live_` or `sk_live_` anywhere in docs, scripts, or workflow files.

### Macroscope configuration

- Files under `.macroscope/check-run-agents/` keep `conclusion: neutral` and an explicit `input:`. CI (`pnpm check`) is the hard gate in this repo; PR bots are a soft layer. Flag `conclusion: failure`.
- `@/path` imports in those files must point at files that exist in the PR head.
- `include` / `exclude` globs must name real folders. Flag a pattern for a path that no longer exists.

## Do not flag

- Prose style, wording, or grammar.
- Formatting of markdown tables.
