You review the Convex backend and the server-side paths of a TanStack Start app that authenticates with Clerk. Convex trusts the Clerk JWT template named `convex`; the app's server function reads Clerk with `auth()` and hands the token to Convex during SSR. Review these paths as a reviewer who knows this repo's invariants.

The Correctness check already finds runtime bugs and logic errors. Do not repeat it. Focus on the repo-specific invariants below.

## Repo brief

@/AGENTS.md

## Convex API rules (generated by `npx convex ai-files`)

@/convex/_generated/ai/guidelines.md

## What to check

### Convex functions

- Every `query`, `mutation`, `action`, `internalQuery`, `internalMutation`, and `internalAction` has `args` **and** `returns`. Lint enforces presence (`@convex-dev/require-args-validator`, `scripts/check-convex-returns.mjs`); you enforce meaning. Flag `v.any()` in `args` or `returns`, and flag a `returns` that re-declares a table's fields instead of `schema.doc("table")` (import `schema` from `./schema`).
- A public function that reads user data calls `ctx.auth.getUserIdentity()` and handles `null`. Flag a new public function that trusts a client-supplied user id, email, or `subject` instead of the identity. `convex/user.ts` shows the pattern and picks fields on purpose; flag a function that returns the whole `UserIdentity` (custom claims vary by JWT template).
- `posts.list` is public and unauthenticated by design (demo data). Do not ask for auth on it. Do flag a new unauthenticated public function that exposes non-demo data.
- Scheduling (`ctx.scheduler.runAfter` / `runAt`) and `ctx.runQuery` / `ctx.runMutation` / `ctx.runAction` target `internal.*` functions. `posts.populate` reading `api.posts.list` is existing code; flag only new `api.*` targets.
- Queries never read the wall clock (`Date.now()`, `new Date()`); time arrives as an argument. Queries return bounded results (`.take(n)` or `.paginate(...)`) unless the caller needs every row and the PR says so. The demo `posts.list` `.collect()` is existing code.
- A change to `convex/schema.ts` ships with the functions that use it and with `convex/_generated/`.

### Tests and generated files

- Every new or changed Convex function has a `convex-test` spec beside it (`convex/<module>.test.ts`, `convexTest({ schema, modules })`, `t.withIdentity({...})` for signed-in behavior). If the diff changes a handler and no test changes, report it once.
- When a PR adds, removes, or renames an exported Convex function, or changes `convex/schema.ts`, `convex/_generated/api.d.ts` and/or `convex/_generated/dataModel.d.ts` must change in the same PR. If they do not, tell the author to run `pnpm convex:generate` and commit `convex/_generated/` (`pnpm convex:check` fails CI otherwise). `convex/_generated/ai/**` is owned by `npx convex ai-files`; do not ask for edits there.
- A nested `INSTRUCTIONS.md` under `convex/` is not allowed.

### Clerk to Convex trust

- `convex/auth.config.ts`: `applicationID` stays `convex` (the Clerk JWT template name) and `domain` stays `process.env.CLERK_JWT_ISSUER_DOMAIN`, read on the **Convex deployment**. Flag a renamed template, a hardcoded issuer, or a move of the variable into `.env*` or `import.meta.env`.
- `src/routes/__root.tsx`: `fetchClerkAuth` is a `createServerFn` that calls `auth()` from `@clerk/tanstack-react-start/server` and `getToken({ template: 'convex' })`; `beforeLoad` calls `serverHttpClient?.setAuth(token)` (SSR only) and returns `{ userId, token }`. Flag a changed template name, a removed `setAuth`, `auth()` called outside the server function, or the token stored anywhere else (cookie, `localStorage`, module global).
- `RootComponent` renders `<ClerkProvider>` outside `<ConvexProviderWithClerk client={context.convexClient} useAuth={useAuth}>`. Flag a swapped order or a removed provider. Source: https://docs.convex.dev/client/tanstack/tanstack-start/clerk
- `src/start.ts`: `requestMiddleware` keeps `csrfMiddleware` and `clerkMiddleware()`. Flag the removal of either, or a change to the `csrfMiddleware` filter.

### Server-only code and environment

- `~/utils/env` (`requireEnv`) and `~/utils/logger` (Winston) are Node-only. They belong in server function handlers and `.server()` middleware bodies. Flag a new call site in code that also runs in the browser: route `head()`, `beforeLoad()`, `loader()`, components, `src/router.tsx`. `scripts/check-hard-rails.mjs` already blocks imports from `src/components/**` and `src/lib/**`; do not repeat those.
- Server logging uses `logger.<level>(message, { structured, fields })`. Flag string-concatenated messages and `console.*` in server code.
- `src/router.tsx` reads `import.meta.env.VITE_CONVEX_URL` (inlined at build time, client-safe) and throws when it is missing. Flag `process.env` or `requireEnv` there.
- Any new `requireEnv('NAME')` or `import.meta.env.VITE_NAME` must appear in `.env.example` with a comment. `CLERK_JWT_ISSUER_DOMAIN` is the exception: it is a Convex deployment variable and `.env.example` says so. Flag a PR that adds it as an app variable.
- Secrets: only `pk_test_...` / `sk_test_...` placeholders in `.env.example`. Flag any literal key, token, or real Clerk issuer URL committed anywhere in the diff.
- `CONVEX_AGENT_MODE=anonymous` is for CI and cloud agents only. Flag it in `.env.example` or in a code path that runs for local developers.

## Do not flag

- Anything `pnpm lint` catches: missing `args` / `returns` validators, old registered-function syntax, `ctx.db.get` / `patch` / `replace` / `delete` without a table name (`@convex-dev/explicit-table-ids`), schema import cycles, `console.*`, missing `import type`, history comments (`do not ... because`), server-only imports from `src/components/**` and `src/lib/**`.
- `.filter()` after `withIndex` and top-of-hour crons: ESLint warns on them already. Mention a new one once; do not repeat per hunk.
- `posts.populate` calling `api.posts.list`, the `Array<Doc<'posts'>>` annotation on that call (avoids a TypeScript circularity), and `posts.list` using `.collect()`. Existing demo code.
- The `!` in `process.env.CLERK_JWT_ISSUER_DOMAIN!` in `convex/auth.config.ts`. Convex fails the push when the variable is missing.
- `skipLibCheck` in `tsconfig.json`.
- Formatting. Biome owns it.
